Operational Excellence

Asks for: run and monitor the system, automate changes, learn from failures.

First pass: deployed by one script, with the dashboard and 10 alarms created at the same time. No runbook yet, no tested restore, and the two automations have not yet run unattended for two nights. Adequate

After: dashboard, 10 alarms, every request logged, two automations, one incident with a written root cause and a tested runbook. Deployment is a script, but it is not automatic from git. Good

Security

Asks for: strong identity, least privilege, protected data, traceability.

First pass: MFA on both our logins, secrets in Parameter Store, no SSH port, HTTPS, CloudTrail on, encrypted disk. Gap: both members have full access to the account through the Team invite, which is wider than least privilege. Adequate

After: MFA on both users, own logins, least-privilege EC2 role, encrypted EBS and S3, CloudTrail, nothing public except 80/443. Open registration on the app is still a weakness. Good

Reliability

Asks for: detect failure, recover automatically or quickly, test recovery.

First pass: a single server in one region and one Availability Zone. Nightly backups are scheduled but have not run yet, and restore is untested. Gap

After: nightly backups, a restore tested in 31 s, site check every 5 min, AI answer check every hour. Still a single server in a single Availability Zone: if it dies we restore by hand (RTO about 25 min, estimated: rebuild the server, then the 31 s restore). Adequate

Performance Efficiency

Asks for: the right resource size, measured.

First pass: t3.small, the largest free-tier-eligible type with enough memory (plus 2 GB swap). Sydney is farther from the Philippines than Singapore, but the account's service control policy only allows ap-southeast-2. Not yet measured. Adequate

After: average CPU FILL-IN %, memory FILL-IN %, average model answer time FILL-IN ms over FILL-IN-DATES. FILL-IN: "right-sized" or "could drop to t3.micro". Adequate

Cost Optimization

Asks for: pay only for what you use, and know what you pay.

First pass: Free plan credits, a USD 30 monthly budget alert from day one, tags on everything. Adequate

After: about 0.45 USD/day (16 to 19 Nov). No idle resources except the Elastic IP, which is billed whether used or not. Free model tier. Good

Sustainability

Asks for: the smallest footprint that does the job.

First pass: one small instance; the unused LibreChat services are not started. It runs 24/7. Adequate

After: one small instance, unused LibreChat services (RAG API, vector DB) not started, logs and backups expire. We run 24/7 for a class project, which is wasteful. Adequate

Our trade-off, and the gap we'd fix first

We optimised for Operational Excellence and Security, because that is what an ops team is judged on and both are cheap to do well. We deliberately accepted weaker Reliability: one server in one Availability Zone, because a second server or a managed database would roughly double the cost of a student project.

Gap we would fix first: move MongoDB off the server (Amazon DocumentDB or MongoDB Atlas free tier) and put the app behind an Auto Scaling group of one. A dead server would then come back by itself in minutes instead of needing a manual restore.
