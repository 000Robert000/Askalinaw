AWS infrastructure design

Region: ap-southeast-1 (Singapore). One server, one database, one bucket, kept small on purpose.

How a question travels

  1. The student's browser connects over HTTPS to the Elastic IP. Caddy holds the free Let's Encrypt certificate and logs one JSON line per request (method, path, status, duration) for CloudWatch.
  2. Caddy passes the request to LibreChat (renamed Askalinaw) running in Docker on port 3080, which is not reachable from outside.
  3. LibreChat checks the login and saves the message in MongoDB.
  4. LibreChat sends the question plus the Askalinaw instructions and handbook to Google Gemini. Only the question and the invented handbook leave AWS.
  5. The answer streams back the same way, and is saved in MongoDB.

Every service and what it is for

ServiceWhat it does here
EC2 t3.medium (2 vCPU, 4 GB) + 2 GB swapRuns Caddy, LibreChat, MongoDB, Meilisearch, cron jobs and the CloudWatch agent. Sized so LibreChat, MongoDB and Meilisearch fit in memory together. Whether it is oversized is checked on the Well-Architected page.
Elastic IP + sslip.ioA fixed address; 1-2-3-4.sslip.io gives us a hostname without buying a domain, so HTTPS works.
S3 (versioned, encrypted, private)AWS integration: the handbook is read from S3 every deploy; uploaded files are stored in S3; nightly backups land in S3 and expire after 14 days.
Systems Manager Parameter StoreAWS integration: every secret (Gemini key, JWT and encryption keys) as SecureString, read at start-up.
Systems Manager Session ManagerShell access without SSH keys or an open port 22.
CloudWatchLogs (retention 7–30 days), metrics, FILL-IN alarms, one dashboard.
SNSAWS integration: sends alarm emails to both of us.
IAM, CloudTrail, BudgetsWho can do what, a record of who did it, and a cost warning.

All of it is created by infra/01-create-aws.sh in our repository, so it can be rebuilt, not just restored.
